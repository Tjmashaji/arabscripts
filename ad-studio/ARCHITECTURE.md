# البنية التقنية

## الطبقات

```
المتصفح (React، عربي RTL)
   │  fetch JSON + رفع ببث مباشر
   ▼
Next.js 16 (App Router)
   ├─ src/app/(app)/…            صفحات محمية (requireUser في layout)
   ├─ src/app/api/…              مسارات API رقيقة: تحقق zod ← خدمة ← JSON
   └─ src/server/
        ├─ http/                 handler: جلسة + CSRF + أخطاء عربية موحدة + حدود الطلبات
        ├─ auth/                 scrypt + جلسات بجدول sessions وكوكي httpOnly
        ├─ db.ts                 withUser(): معاملة يُضبط فيها app.user_id لتطبيق RLS
        ├─ services/             منطق الأعمال (مشاريع، وسائط، مشاهد، مهام، قوالب، تصدير)
        ├─ providers/            واجهات المزودين + محوّلاتهم + المحاكاة + السجل (registry)
        └─ media/                التخزين، تحديد النوع، ffprobe، ASS، محرك التصدير
PostgreSQL ◄──────────────────────┐
   ▲                               │ studio_worker (يتجاوز RLS)
   │ studio_app (يخضع لـ RLS)      │
   │                         src/worker/  عامل خلفي: يحجز مهمة ← خطوة ← يحدّث الحالة
   │                               │
   └── التخزين (STORAGE_DIR) ◄─────┴── FFmpeg / Claude / ElevenLabs / Runway
```

## فصل المسؤوليات

| الطبقة | المكان | ملاحظة |
|---|---|---|
| الواجهة | `src/app`, `src/components` | لا تحمل أي سر؛ تتحدث مع `/api` فقط |
| منطق الأعمال | `src/server/services` | كل دالة تستقبل `Tx`، فتعمل من الويب (RLS) ومن العامل |
| البيانات | `db/migrations` | المخطط + RLS + دوال SECURITY DEFINER للمصادقة |
| الذكاء الاصطناعي | `src/server/providers` | واجهة لكل قدرة، ومحوّل لكل مزود، والسجل يختار المتاح |
| معالجة الوسائط | `src/server/media` | التخزين وffprobe والتصدير؛ مستقلة عن الذكاء الاصطناعي |
| المهام | `src/server/services/jobs.ts`, `src/worker` | الإنشاء في الويب، والتنفيذ في العامل |
| المصادقة والصلاحيات | `src/server/auth`, `0002_security.sql` | الجلسة في التطبيق، والصلاحية في قاعدة البيانات |
| الفوترة والرصيد | `plans`, `subscriptions`, `usage_ledger`, `app.month_spend_cents` | سقف إنفاق شهري؛ الدفع غير مفعّل |

## رحلة الإعلان

1. **إنشاء المشروع**: يُنشئ `brands` و`projects` و`editing_timelines`.
2. **الرفع**: `POST /api/projects/:id/media` يبث الجسم إلى التخزين بحد للحجم، ثم يحدد النوع من البايتات (لا من الاسم)، ثم يقرأ الأبعاد والمدة بـ ffprobe، ثم يُدرج السجل. إذا كان التحليل متصلًا تُنشأ مهمة `analyze_media`.
3. **المخرج الإبداعي**: `POST /api/projects/:id/director` يبني الملخص من البيانات الفعلية (`buildBrief`)، ويحفظه في `creative_briefs`، ثم يُنشئ مهمة `director`. العامل يستدعي المزود ويتحقق من المخرجات ويصلحها (`repair.ts`)، ثم يحفظ نسخة جديدة من `scripts` ويستبدل المشاهد مع حذف القديمة حذفًا منطقيًا.
4. **التوليد**: مهمة مستقلة لكل مشهد (`generate_video` و`generate_image`)، تمر بالإرسال ثم الاستعلام الدوري ثم التنزيل والتخزين ثم `scene_generations`، ويصبح الناتج مادة المشهد.
5. **الصوت**: مهمة `generate_speech` لكل جملة (مشهد)، فيمكن إعادة توليد جملة واحدة.
6. **المونتاج**: ترتيب المشاهد ومددها وانتقالاتها في جدول `scenes`، وإعدادات المزج والنصوص والشعار والمقاس في `editing_timelines.data`، مع قفل تفاؤلي بالنسخة.
7. **التصدير**: `buildRenderPlan` يحوّل حالة المشروع إلى خطة تحتوي ملفات فعلية فقط، ويكشف المشاكل قبل البدء. بعدها ينفّذ `render()` أمر FFmpeg ويتحقق من الناتج (الأبعاد والمدة ووجود الصوت والصورة)، ثم يُحفظ في `exports`. الإعدادات محفوظة، فيمكن إعادة التصدير بأي مقاس دون إعادة التوليد.

## نظام المهام

- الحالات: `queued` و`processing` و`completed` و`failed` و`cancelled`.
- **منع التكرار**: كل طلب يحمل `idempotency_key` فريدًا لكل مساحة عمل. إعادة إرسال نفس الطلب (نقر مزدوج أو انقطاع اتصال) تعيد المهمة نفسها، ولا تنشئ مهمة جديدة ولا تكرر الخصم.
- **الحجز**: `UPDATE … WHERE id = (SELECT … FOR UPDATE SKIP LOCKED)`، فيمكن تشغيل أكثر من عامل. إذا توقف عامل، تُستعاد مهمته بعد 10 دقائق.
- **المزود غير المتزامن**: تبقى المهمة `processing` مع `provider_job_id` و`run_after`، ويُستعلم عنها لاحقًا دون حجز العامل ودون إبقاء طلب HTTP مفتوحًا.
- **إعادة المحاولة**: للأخطاء القابلة لذلك فقط (ازدحام، شبكة، 5xx)، بتأخير `15×2^n` ثانية حتى `max_attempts`. الأخطاء النهائية (مفتاح خاطئ، رفض المحتوى) تفشل فورًا برسالة عربية.
- **التقدم**: نسبة رقمية فقط إذا أعادها المزود (Runway وFFmpeg)، وإلا وصف نصي.
- **التكلفة**: تُسجَّل في `usage_ledger` مرة واحدة لكل مهمة (فهرس فريد)، مع علامة «تقديرية» حين لا يعيد المزود مبلغًا نهائيًا.

## الأمان

- **RLS** على كل الجداول. تطبيق الويب يتصل بدور لا يملك `BYPASSRLS`، ويضبط `app.user_id` داخل كل معاملة. الوصول للحسابات والجلسات قبل الدخول يمر عبر دوال `SECURITY DEFINER` محددة فقط.
- **المهام**: صلاحيات الأعمدة تمنع تطبيق الويب من تعديل أي عمود في `ai_jobs` عدا `cancel_requested`.
- **CSRF**: كل طلب معدِّل يجب أن يأتي من `APP_URL` نفسه، والكوكي `SameSite=Lax` و`httpOnly`.
- **الرفع**: النوع يُحدد من البايتات، وSVG وHTML مرفوضان. حد للحجم أثناء البث، وحد لعدد الرفعات في الساعة.
- **تقديم الملفات**: `Content-Security-Policy: sandbox` و`nosniff`، والرابط الموقّع له صلاحية محدودة.
- **حقن البرومبت**: بيانات المستخدم تُمرَّر للنموذج داخل `<brief>` و`<user_idea>` مع تعليمات صريحة بمعاملتها كبيانات. نصوص المستخدم داخل الفيديو تُنظف من أوامر ASS.
- **التكاليف**: سقف إنفاق شهري لكل مساحة يُفحص قبل إنشاء أي مهمة مدفوعة، مع حدود لمعدل طلبات التوليد.
- **الأسرار**: في متغيرات بيئة الخادم فقط، ولا يوجد أي مفتاح في كود الواجهة.

## قرارات مهمة

- **Postgres بدل Supabase**: يمكن تشغيل المنصة واختبارها كاملة محليًا، بما في ذلك العامل وFFmpeg. والانتقال لاحقًا إلى Supabase ممكن، لأن الصلاحيات مكتوبة كـ RLS في SQL.
- **التصدير عبر FFmpeg مباشرة**: مع ASS وlibass للعربية، لأن `drawtext` لا يعالج اتجاه النص العربي بشكل صحيح.
- **بلا Cache Components**: كل البيانات ديناميكية لكل مستخدم.
- **بلا `proxy.ts`**: الحماية في `layout` الصفحات وفي كل مسار API. هذا يتجنب أيضًا تخزين جسم الرفع مؤقتًا في الـ proxy.

## إضافة محوّل تخزين سحابي

نفّذ `StorageAdapter` (`put` و`read` و`size` و`localPath` و`remove`). في التخزين السحابي، تنزّل `localPath` الملف إلى مجلد مؤقت لأن FFmpeg يحتاج مسارًا محليًا. بعدها استبدل الإنشاء في `storage()`.
