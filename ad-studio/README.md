# استوديو الإعلانات الذكي (AI Advertising Studio)

منصة عربية لإنتاج الإعلانات: من بيانات النشاط والصور والمقاطع الحقيقية إلى فكرة وسيناريو ومشاهد وتعليق صوتي ومونتاج، ثم فيديو نهائي بمقاس كل منصة.

> المشروع مستقل داخل المستودع `arabscripts`، ولا يمس `masari/` أو `arab-scripts/`. انظر `PROJECT_AUDIT.md`.

## ما يعمل الآن وما يحتاج إعدادًا

| الوظيفة | الحالة |
|---|---|
| الحسابات والجلسات وعزل البيانات بـ RLS | تعمل ومختبرة |
| المشاريع ومعالج الإنشاء وحفظ التقدم | تعمل ومختبرة |
| رفع الصور والفيديو والصوت (تحقق من المحتوى والحجم، روابط موقعة مؤقتة) | تعمل ومختبرة |
| مكتبة القوالب (7 قوالب نظام + نسخ وتعديل وقوالب خاصة) | تعمل |
| محرر السيناريو والمشاهد (تعديل، ترتيب بالسحب، إضافة، تكرار، حذف، نسخ البرومبت) | يعمل ومختبر |
| نظام المهام غير المتزامن والعامل الخلفي (إعادة المحاولة، الإلغاء، منع التكرار) | يعمل ومختبر |
| محرر المونتاج (ترتيب، مدد، انتقالات، صوت، موسيقى، نصوص، شعار، مقاس، حفظ تلقائي) | يعمل |
| التصدير عبر FFmpeg (نصوص عربية سليمة، انتقالات، شعار، مزج الصوت وخفض الموسيقى، التحقق من الملف) | يعمل ومختبر |
| المخرج الإبداعي وتحليل الصور (Claude) | **يحتاج `ANTHROPIC_API_KEY`**؛ المحوّل مكتوب ومختبر بشبكة مُحاكاة |
| التعليق الصوتي (ElevenLabs) | **يحتاج `ELEVENLABS_API_KEY`**؛ مختبر بشبكة مُحاكاة |
| توليد الفيديو (Runway) | **يحتاج `RUNWAY_API_KEY`**؛ مختبر بشبكة مُحاكاة |
| توليد الصور | واجهة ومحاكاة فقط؛ لا يوجد مزود صور حقيقي مدمج بعد |
| الدفع والاشتراكات | البنية جاهزة (خطط، اشتراكات، سجل استخدام)، **والدفع غير مفعّل** |

بدون مفاتيح، تعمل المنصة في **وضع المحاكاة** (خارج الإنتاج فقط): كل مخرج محاكاة موسوم بوضوح في الواجهة، ويحمل الفيديو المصدَّر وسم «محاكاة — ليست نتيجة إنتاج». لا توجد محاكاة لتحليل الصور، حتى لا ندّعي تحليل ملف لم يُحلَّل.

## التشغيل على جهازك بأمر واحد (Docker)

لا تحتاج تثبيت Node أو PostgreSQL أو FFmpeg، يكفي [Docker Desktop](https://www.docker.com/products/docker-desktop).

1. شغّل Docker Desktop وانتظر حتى يجهز.
2. **ويندوز**: افتح مجلد `ad-studio` واضغط مرتين على `start.bat`.
   **ماك أو لينكس**: من الطرفية داخل المجلد: `bash start.sh`.
3. أول مرة تأخذ 5 إلى 10 دقائق للبناء، ثم يفتح المتصفح على `http://localhost:3000`.

- أول تشغيل ينشئ ملف `.env` بأسرار عشوائية خاصة بجهازك. فيه تضيف مفاتيح الخدمات وتغيّر `ALLOW_SIMULATION`، ثم تشغّل `start` من جديد.
- افتح المنصة على `localhost` تحديدًا (لا `127.0.0.1`)، لأن التحقق من أصل الطلبات يقارن به.
- للإيقاف: `stop.bat` أو `bash stop.sh`. الحسابات والمشاريع والملفات تبقى محفوظة.
- إذا كان المنفذ 3000 مشغولًا، غيّر `STUDIO_PORT` في `.env`.

## المتطلبات

- Node.js 22.13 أو أحدث
- PostgreSQL 14 أو أحدث (مختبر على 16)
- FFmpeg وffprobe مبنيان مع libass وlibharfbuzz وlibfribidi وlibx264، وهي متوفرة في حزمة ffmpeg في Ubuntu وDebian. هذه المكتبات لازمة لكتابة العربية داخل الفيديو.

## التشغيل محليًا

```bash
cd ad-studio
npm install

# 1) قاعدة البيانات: الأدوار الثلاثة ثم القاعدة (يتطلب صلاحية superuser)
PGPASSWORD=<كلمة مرور postgres> ./db/setup-local.sh

# 2) متغيرات البيئة
cp .env.example .env.local    # ثم عدّل كلمات المرور وFILE_SIGNING_SECRET
set -a && . ./.env.local && set +a

# 3) الترحيلات وقوالب النظام
npm run db:migrate
npm run db:seed

# 4) التطبيق والعامل الخلفي (في طرفيتين)
npm run dev
npm run worker
```

ثم افتح `http://localhost:3000`.

كلمات مرور الأدوار الافتراضية في `setup-local.sh` للتطوير فقط. في الإنتاج مرّر `STUDIO_OWNER_PASSWORD` و`STUDIO_APP_PASSWORD` و`STUDIO_WORKER_PASSWORD`.

## التخزين

التخزين الحالي محلي في `STORAGE_DIR`. كل ملف مربوط بمساحة عمل ومشروع، ويُقدَّم إما للعضو المسجّل (تتحقق منه RLS) أو برابط موقّع بـ HMAC وصالح لمدة محدودة. لاستخدام S3 أو Supabase Storage نفّذ الواجهة `StorageAdapter` في `src/server/media/storage.ts` (انظر `ARCHITECTURE.md`).

## مزودو الذكاء الاصطناعي

أضف المفاتيح في متغيرات بيئة **الخادم والعامل** (لا تصل للمتصفح إطلاقًا)، ثم أعد التشغيل. حالة كل خدمة تظهر في «الإعدادات». التفاصيل وإضافة مزود جديد في `AI_PROVIDERS.md`.

## الاختبارات

```bash
./tests/global-db.sh     # قاعدة اختبار نظيفة (ad_studio_test)
npm test                 # وحدات + تكامل (قاعدة حقيقية + FFmpeg + العامل)
npm run test:e2e         # المتصفح؛ يتطلب تشغيل التطبيق والعامل مسبقًا
npm run typecheck && npm run lint
```

التفاصيل والنتائج في `TESTING.md`.

## الإنتاج

```bash
npm run build && npm run start   # خادم الويب
npm run worker                   # العامل الخلفي (عملية منفصلة دائمة)
npm run cleanup                  # يوميًا عبر cron: سياسة الاحتفاظ والحذف
```

- العامل وFFmpeg يحتاجان خادمًا أو حاوية دائمة (Railway أو Fly.io أو VPS)، ولا يعملان على Vercel Serverless. يمكن تشغيل أكثر من عامل بأمان.
- **Railway**: خطوات النشر كاملة في `DEPLOY_RAILWAY.md` (`Dockerfile` و`railway.json` جاهزان).
- اجعل `ALLOW_SIMULATION=false` في الإنتاج.
- ضع `APP_URL` بالرابط العام. يُستخدم للتحقق من أصل الطلبات (CSRF).
